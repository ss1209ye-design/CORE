# 꿀잡

> **취업을 픽! 나의 경험에서 다음 준비까지, 꿀잡.**

꿀잡은 흩어진 채용 공고와 개인 경험을 연결하는 취업 준비 웹앱입니다. 관심 공고의 지원 기간을 **피기캘린더**에서 확인하고, 차곡차곡 기록한 경험을 AI 키워드·자기소개서·면접 연습에 재사용합니다. 돼지 가이드 **피기(Piggy)**가 서비스 이용을 안내합니다.

환경 준비는 [개발환경 안내](docs/SETUP.md), 기능과 AI 설정은 [화면·사용 안내](docs/UI_UX.md)를 참고하세요.

## 프로젝트 개요

- 한 줄 소개: 공고 관리와 경험 기록을 연결하는 취업 준비 공간입니다.
- 누구를 위한 앱인가: 물리치료 전공 졸업예정자·신입·이직 준비자를 출발점으로 보건의료 분야 활용을 목표로 합니다.
- 어떤 상황에서 쓰는가: 공고의 일정·조건을 정리하고 자신의 경험을 지원서와 면접 답변에 활용할 때 사용합니다.
- 기본 흐름: 회원가입·로그인 → 공고 링크 저장 또는 경험 등록 → 키워드 추출 → 자기소개서 → 면접 연습·복기.
- 현재 단계: 해커톤 MVP. 공고 자동 분석은 사용하지 않습니다.

**해결하려는 문제**

공고 링크는 여러 곳에 흩어져 있고, 실습·활동 기록은 지원서를 쓸 때 다시 정리해야 합니다. 꿀잡은 공고의 일정 관리와 개인 경험 활용을 하나의 흐름으로 묶어, 준비 자료를 반복해서 옮겨 적는 부담을 줄이는 것을 목표로 합니다.

| 사용자가 겪는 문제 | 꿀잡의 접근 |
| --- | --- |
| 여러 공고의 접수 기간을 따로 확인해야 한다 | 직접 확인한 시작일·마감일을 피기캘린더에 표시한다 |
| 경험은 있지만 지원서에 어떻게 쓸지 막막하다 | 작성한 경험에서 키워드와 원문 근거를 함께 찾는다 |
| 자기소개서와 면접 준비가 따로 진행된다 | 저장한 자기소개서를 면접 질문·답변·복기에 연결한다 |
| AI가 만든 문장이 내 경험과 일치하는지 불안하다 | 근거 확인·수정 과정을 두고 부족한 정보를 구분한다 |

**제품의 차별점**

꿀잡이 집중하는 지점은 사용자가 공고를 발견한 이후의 준비 과정입니다. 직접 모은 공고와 개인 기록을 연결하고, 동일한 경험을 키워드 → 자기소개서 → 면접 답변으로 이어서 활용하도록 설계합니다. 이는 제품의 설계 방향이며, 다른 서비스보다 우수하다는 비교 실험 결과를 뜻하지 않습니다.

예를 들어 실습 중 관찰한 내용을 포트폴리오에 기록하면, 그 내용에서 키워드를 확인하고 선택한 경험으로 자기소개서 초안을 준비할 수 있습니다. 이후 저장한 자기소개서를 바탕으로 질문을 받아 답변을 연습합니다. 관찰 경험을 독립적으로 수행한 경력으로 바꾸지 않는 것이 핵심 원칙입니다.

## 주요 기능

| 과제의 꼭 있어야 하는 기능 | 화면(프론트엔드) | API(백엔드) |
| --- | --- | --- |
| 회원가입·로그인·로그아웃 | 인증 화면·마이페이지 | Better Auth, Supabase PostgreSQL 계정·세션 저장 |
| 공고 링크 저장·직접 입력 | 공고 등록·목록·피기캘린더 | 계정별 서버 저장, 별도 공고 분석 API 없음 |
| 포트폴리오·키워드 추출 | 경험 입력, 키워드 태그 수정·삭제 | 인증된 `/api/ai`에서 BAZE를 통한 Gemini 키워드 생성 |
| 자기소개서 준비 | 경험·문항 선택, 초안·수정본·제출본 저장; 공고 연결 선택 | `/api/ai`에서 선택 자료 기반 초안 생성 |
| 면접 연습·복기 | 자기소개서 기반 질문, 답변·꼬리 질문·피드백·복기 | `/api/ai`에서 질문·피드백 생성 |

2026-10-30 확인 기준입니다. 학교 BAZE를 통해 가상 자료의 키워드 3개·자소서 초안·면접 질문 5개·답변 피드백을 실제 서버 생성 함수로 호출하고 JSON·원문 근거 검증을 통과했습니다. 인증·저장 이전 후 전체 테스트 75개와 타입·린트·포맷·빌드 검사도 통과했습니다. 기존 SQLite 전용 테스트는 PostgreSQL·서버 저장 검증으로 교체했습니다. 이는 브라우저 전체 흐름이나 Vercel 운영 배포 성공을 뜻하지 않습니다.

더 만든 기능: 피기 서비스 안내, 3D 캐릭터, 반응형 화면, 시연용 가상 경험 5개, 경험 근거 표시, AI 실패 시 입력 보존 처리가 있습니다. AI 결과는 사용자가 확인·수정하며 없는 경험·성과를 사실로 제공하지 않는 것을 원칙으로 합니다.

공고는 링크만 저장한 뒤 기관명·직무·조건·서류·날짜를 보완할 수 있습니다. 날짜가 미확인인 공고에는 임의 일정을 만들지 않습니다. 사진 인식·OCR·URL 본문 자동 수집은 현재 사용하지 않습니다. 현재 API 경로에는 사진·URL 공고 분석 라우트가 없습니다.

**피기캘린더**

확인한 시작일과 마감일이 모두 있으면 지원 기간으로, 한쪽만 확인되면 해당 날짜의 일정으로 표시합니다. 주·월을 넘는 기간과 겹치는 공고를 배치하는 코드가 있으며, 캘린더에서 공고 상세로 이동할 수 있습니다. 날짜가 없는 공고는 임의 일정 없이 보관합니다.

**AI 결과 처리 원칙**

- 사용자가 선택한 자료를 바탕으로 생성하고 원문 근거를 함께 확인합니다.
- 키워드와 초안은 수정·저장할 수 있으며, 최종 제출 내용은 사용자가 확인합니다.
- 설정 누락이나 AI 호출 실패를 고정된 성공 응답으로 대체하지 않습니다.
- 사실성 검증에는 한계가 있으며, AI 결과를 경력 증명이나 합격 가능성 판단으로 사용하지 않습니다.

## 기술 스택

- 프론트엔드: Next.js 16.4.3 App Router, React 19, TypeScript, Tailwind CSS 4, Three.js.
- 백엔드: Next.js 서버 기능·Route Handler, Better Auth, Zod.
- 데이터(어디에, 무엇을): 계정·세션·요청 제한과 공고·경험·키워드·자소서·면접 기록은 Supabase PostgreSQL에 저장합니다. Better Auth와 `pg`를 사용하며, 준비 기록은 세션의 사용자 ID를 소유자로 하는 JSON 문서로 저장합니다. 기존 Prisma 예시 모델과 Supabase Auth 서비스는 로그인에 사용하지 않습니다.
- AI: 학교 BAZE API Gateway를 통해 Google Gemini SDK로 호출합니다. `src/lib/ai-contract.ts`의 고정 모델 `gemini-3.6-flash`는 학교 키로 모델 목록과 실제 응답을 확인했습니다. 학교 지원 크레딧을 사용하며, 조직별 잔여 한도는 학교 BAZE 관리자에게 확인해야 합니다.

**데이터 보관:** 같은 계정으로 로그인하면 서버의 기록을 다시 조회합니다. 기존 계정별 브라우저 기록은 해당 계정으로 접속할 때 중복 없이 서버로 합치며 원본은 삭제하지 않습니다. 동일 ID의 내용이 충돌하면 서버 자료를 유지하고 안내합니다. 기존 자료 이전은 원래 사용하던 주소에서 먼저 진행하세요. 다른 출처의 브라우저 저장소는 읽을 수 없습니다. 동시에 열린 화면은 새로고침으로 최신 자료를 읽으며 오래된 버전의 저장은 거절합니다.

## 실행 방법

1. Node.js 24.x를 준비하고 프로젝트 폴더에서 터미널을 엽니다.
2. 의존성을 설치합니다.

   ```sh
   npm ci
   ```

3. 처음 설치한 환경에서 인증 설정을 준비합니다. 기존 `.env.local`과 `.data/`를 삭제하거나 덮어쓰지 마세요. 인증이 정상인 환경에서는 재초기화할 필요가 없습니다.

   ```sh
   npm run auth:setup -- --preview
   ```

4. 개발 서버를 실행합니다.

   ```sh
   npm run dev -- --hostname 127.0.0.1
   ```

5. [http://localhost:3000](http://localhost:3000)에 접속합니다. 이는 실행 중인 컴퓨터의 로컬 주소이며 팀원용 공개 배포 주소가 아닙니다.

AI 기능에는 기존 `.env.local`에 다음 서버 전용 설정이 필요합니다. `=` 뒤에 학교 BAZE 키를 직접 입력하고 다른 설정은 유지하세요.

```dotenv
BAZE_API_KEY=
```

키는 [학교 BAZE](https://factchat-cloud.mindlogic.ai)의 **API Gateway**에서 발급합니다. SDK 기본 주소는 `https://factchat-cloud.mindlogic.ai/v1/gateway/gemini`, API 버전은 `v1beta`, 인증은 `x-goog-api-key`입니다. 주소와 모델은 코드에 고정되어 별도 환경변수는 필요하지 않습니다. 기존 `GEMINI_API_KEY`·`GEMINI_FREE_TIER_CONFIRMED`는 사용하지 않습니다. 개발 도구의 셸·Codex 설정과 웹앱 연결은 별개입니다.

Vercel에서는 프로젝트 **Settings → Environment Variables**에 `BAZE_API_KEY`를 직접 등록하고 적용 환경을 선택한 뒤 재배포합니다. `NEXT_PUBLIC_`를 붙이지 말고 키를 채팅·Git·캡처에 공개하지 마세요. 인증·기록 DB는 아래 서버 설정도 필요합니다.

학교 지원 크레딧이 사용됩니다. 앱은 잔여 크레딧·학교 결제 설정을 조회하지 않으므로 지원 한도는 학교 관리자에게 확인하세요. 한도 오류 시 입력을 보존하고 중단하며, 자동 재시도·별도 결제·다른 서비스로의 자동 전환은 하지 않습니다.

저장 후 **앱 서버를 실행한 터미널**에서 `Ctrl+C`로 중지하고 같은 명령으로 다시 시작합니다. 재시작을 위해 기록이나 DB를 삭제할 필요는 없습니다. AI 요청에는 선택한 경험·자소서·답변 등이 외부 서비스로 전달될 수 있으므로 시연에는 가상 자료를 사용하세요.

빌드한 앱은 다음 명령을 순서대로 실행합니다.

```sh
npm run build
npm run start -- --hostname 127.0.0.1
```

코드 검사 명령입니다. `check`는 타입·린트·포맷 검사이며 실제 AI 호출 성공을 뜻하지 않습니다.

```sh
npm run typecheck
npm run lint
npm run format:check
npm run check
```

**확인해야 할 핵심 시나리오**

| 확인 대상 | 통과 기준 |
| --- | --- |
| 공고·캘린더 | 링크만 저장 가능, 확인한 기간 표시, 수정·재조회 시 일치 |
| 포트폴리오 | 작성·저장·재조회, 키워드 수정·삭제, 실패 시 입력 유지 |
| 자기소개서 | 공고 없이 선택한 경험으로 초안 생성·수정·재조회 |
| 면접 | 자기소개서 기반 질문·답변·복기 저장 및 재조회 |
| 인증 | 로그인·로그아웃, 인증 없는 AI 요청 차단 |
| 실제 AI | 가상 자료로 실제 응답 확인, 오류와 정상 결과 구분 |

이 표는 확인 기준이며 통과 실적이 아닙니다. 검사 날짜·환경·결과와 미검증 사유를 별도로 기록해야 합니다.

기능별 테스트는 `scripts/*.test.ts`에 있습니다. 테스트 대역 결과와 실제 AI 호출 검증은 구분해 기록합니다. 현재 `package.json`에는 `npm test` 명령이 없습니다.

배포 주소(있으면): 아직 확인된 공개 주소는 없습니다. **SQLite 런타임 의존성은 PostgreSQL로 이전했고 로컬 로그인·기록 저장·빌드 검증을 통과했습니다.** Vercel 프로젝트의 Production 환경변수는 `DATABASE_URL`(Transaction pooler), `BETTER_AUTH_SECRET`(기존 값 유지), `BETTER_AUTH_URL`(실제 HTTPS 배포 원점), `BAZE_API_KEY`입니다. `DIRECT_URL`과 SQLite 경로는 배포 런타임에 넣지 않습니다. CA 인증서는 빌드에 포함합니다. Vercel에서 로그인·로그아웃·쿠키·DB 연결을 확인하기 전까지 운영 배포 완료로 간주하지 않습니다.

DB 설정은 `DATABASE_URL`, `DIRECT_URL`, 기존 인증 URL·비밀값을 로컬 비공개 환경에 입력한 뒤 진행합니다. `npm run auth:setup -- --preview`는 구조 확인만 수행합니다. 빈 DB 초기화는 `npm run auth:setup -- --apply`, 기존 SQLite 계정 이전은 `npm run auth:setup -- --apply --from-sqlite`입니다. 이전은 일관된 비공개 백업을 만들고 ID·비밀번호 해시·행 값을 비교합니다. 대상 계정 테이블이 비어 있지 않으면 재이전을 거절하며 원본 DB를 삭제하지 않습니다. 이미 이전된 현재 프로젝트에서 초기 이전을 반복 실행하지 마세요.

## AI 활용 내역

- 사용한 도구: **ChatGPT**를 기획·요청 정리에, **GJC(가재코드)**를 저장소 분석·코드 수정·검사·Git 작업에 사용했습니다. 이번 대화에서 확인된 실행 도구는 GJC이며 내부 모델명을 추측하지 않습니다. **제품 내 AI**는 학교 **BAZE API Gateway → Gemini `gemini-3.6-flash`**로, 개발 보조 AI와 구분합니다.
- 주요 프롬프트와 수정 결과: 아래 인용은 사용자가 실제로 한 요청입니다. 제품 기능·설정 결정은 사용자가 했고, GJC가 구현·검사를 수행했습니다.

- AI가 만든 것 / 사람이 고친 것: 사용자가 학교 API 사용 가능 여부 확인, 키·DB 비밀번호 입력, 기능 우선순위·보존 정책 결정 및 GitHub Desktop 푸시를 수행했습니다. GJC는 인증·기록 API·비동기 저장·테스트·문서를 수정했습니다. 비밀값을 README나 Git에 넣지 않았습니다.
- 결과를 확인한 방법: 실제 BAZE 호출, PostgreSQL 이전값 비교, 가상 로그인, 독립 Chrome 컨텍스트의 기록 API 호출, 전체 테스트 75개, 타입·린트·포맷 검사와 프로덕션 빌드로 확인했습니다. DB 테스트에서 동일 클라이언트 병렬 호출 관련 pg 차기 버전 경고가 있었으며 운영 요청 한도 오류는 아닙니다. 헤더 없는 직접 인증 검사에서는 IP를 알 수 없어 요청 제한 버킷을 공유한다는 경고가 발생했습니다. Vercel에서는 신뢰할 수 있는 플랫폼 IP 헤더 전달과 실제 로그인 동작을 배포 후 확인해야 합니다.
